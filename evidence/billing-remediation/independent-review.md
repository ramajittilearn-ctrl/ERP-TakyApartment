## BR-01: high, prepared-run can mutate an unvalidated ambient database

`scripts/run-remediation-browser.mjs` loads `.local/remediation-${runId}.env` at lines 77-81 without checking dotenv's returned error or checking that parsed configuration belongs to the planned run. It immediately invokes Prisma migrations, seed, and test-user writes at lines 84-86. The new `--prepared-run` entry point skips provisioning, so a nonexistent or unreadable plan leaves the inherited `DATABASE_URL` active. A mismatched plan can likewise point elsewhere. Browser nonce/role verification runs much later, after those mutations. The test-user script's database basename check does not protect the preceding migration and seed.

Required correction: fail closed before migration, seed, proxy startup, or cleanup. Load a real run-specific environment and Compose document, validate exact loopback database endpoint 55452, database `taky_phase2_test`, generated role `e2e_RUN_ID`, run ID, origin, proxy configuration, and Compose project/role/database/published endpoint. Do not execute `compose down` against an unvalidated document in finally. Prove missing and mismatched plans cannot spawn migration/seed/Docker using subprocess tests with harmless command shims. Main should also retain the actual connected identity proof for the valid run.

Sent to implementation owner and Main for correction.

## BR-02: medium, period switch temporarily labels the prior period's selected rates as the new period

`src/features/billing/setup-panel.tsx` retains `history` when a new nonempty `periodId` starts loading at lines 145-161. `latestSelection` at lines 197-204 consumes every retained history row without checking its `billingPeriodId`. After changing from period A to B, B's heading and summary render immediately while A's selected amount/reason/revision continue rendering until B's request completes. A slow request can leave incorrect financial context visible for an extended time.

Required correction: associate history with its loaded period, or filter by the current period before displaying either latest selection or details. Clear stale success/error context appropriately and display loading while B's history is unknown. Verify switching from populated A to empty or delayed B never displays A's approved values under B. An abort alone does not remove already stored A data.

Sent to implementation owner for correction.
